# Спецификација: мерлива изведба (бенчмарк + буџети)

Статус: фаза А (мерење) — спроведена; фаза Б (оптимизации) — план во `plan.md`.

## Проблем

Со секоја нова знаменитост и стил мапата е потешка за прелистувачот. На машината на сопственикот
(MacBook Pro 15" 2018/19: i7 6 јадра 2.2 GHz, Radeon Pro 555X 4 GB + Intel UHD 630, 16 GB,
Retina) веќе има сецкање. Досега мерењата беа само во headless Chromium (SwiftShader, софтверски) —
FPS таму е 1–9 и не кажува ништо за вистинскиот уред, а не знаеме **каде** оди времето
(сенки? пост-ефекти? дрвја? резолуција?).

## Цел

Проектот да стане **мерлив**: секоја промена (нова знаменитост, стил, ефект, оптимизација) да
може да се измери на ист начин, на вистинскиот уред и во CI-средина, со бројки што се споредуваат
со буџет и со претходна основа.

## Корисници

- Сопственикот — пушта мерење на својот MacBook во Chrome и ги праќа/комитува резултатите.
- Агентот/развивачот во cloud сесија — headless мерење на структурата на кадарот (повици,
  триаголници) за да фати регресии пред да стигнат до уредот.

## Функционални барања

| ID | Барање |
|---|---|
| P1 | **Мерење во живо** (`?debug`): интервал меѓу кадри (p50/p95), CPU по фаза од јамката (update, render, labels), GPU време по пас (scene, shadow, gtao, output, postcard, tiltshift), повици, триаголници, резолуција (DPR, пиксели). |
| P2 | **Бенчмарк** (`?bench[=quick\|standard\|ablation]`): ист сценарио секој пат — стил × време × поглед + лет низ градот; загревање, па мерење на N кадри; извештај како табела и JSON (копирај / сними). |
| P3 | **Аблација** („каде оди времето“): на ист поглед се исклучува дел по дел — дрвја, згради, знаменитости, релјеф, улици, сенки, пост-ефекти (поединечно), DPR 1.5 / 1, MSAA, blur зад панелите, „минимум“ — и се пресметува цената на секој дел (Δ ms, Δ %). |
| P4 | **Опис на уредот** во секој извештај: GPU (UNMASKED_RENDERER), прелистувач, DPR, големина на canvas во пиксели, MSAA, профил, commit. Мора да се види дали WebGL работи на Radeon или на Intel. |
| P5 | **Буџети** (`src/config/perf.js`) — цели за референтниот уред; извештајот ги означува ✓/✗. Времињата се проверуваат само со вистински GPU; структурата секогаш. |
| P6 | **Runner** (`npm run bench`): Playwright, headless SwiftShader (структура) или `--gpu` (вистински GPU, видлив прозорец, по желба `--uncapped`); JSON во `docs/perf/results/`; споредба со основа (`--baseline`, `--compare`), `--check` → излез 1 при регресија > 10 %. |
| P7 | Без мерење (`?debug`/`?bench` отсутни) инструментацијата е исклучена — нула трошок за обичниот корисник; бенчмаркот е посебен модул што се вчитува динамички. |

## Метрики

| метрика | што значи | извор |
|---|---|---|
| интервал меѓу кадри (p50, p95, p99) | тоа што корисникот го гледа (со vsync: 16.7 ms = 60 fps) | `requestAnimationFrame` |
| % сецкање | удел на кадри > 25 ms (пропуштен vsync на 60 Hz) | интервал |
| CPU ms по фаза | JS во јамката: камера/стил (`update`), предавање на цртањето (`render`), натписи (`labels`) | `performance.now()` |
| GPU ms по пас | вистинско време на графичкиот процесор, вкл. сенки посебно | `EXT_disjoint_timer_query_webgl2` (Chrome/Edge) |
| повици, триаголници | структура на кадарот — детерминистичко, не зависи од уредот | `renderer.info` |
| вчитување | податоци, градење, прв кадар; смена на стил + „удар“ на првиот кадар (компајлирање шејдери) | `window.__bitola` |
| меморија | програми, геометрии, текстури, JS heap | `renderer.info`, `performance.memory` |

Зошто GPU ms, а не само fps: со vsync fps е заглавен на 60 сè додека има резерва, па не кажува
колку сме блиску до работ. GPU ms (и CPU ms) ја покажуваат резервата и се споредливи меѓу верзии.

## Нефункционални барања

- Инструментацијата не смее да го менува тоа што се мери (кругови без вгнездување; без `gl.finish`).
- Резултатите се репродуцибилни: фиксни погледи, фиксен редослед, загревање пред мерење,
  враќање на состојбата по секоја аблација.
- Извештаите се JSON со `schema: 1` — компатибилни за споредба меѓу верзии.

## Критериуми за прифаќање (фаза А)

1. `?debug` покажува CPU по фаза и GPU по пас во живо (или „нема тајмер“).
2. `?bench` завршува без грешки на десктоп и телефонски профил, табелата и JSON се достапни.
3. `npm run bench` работи headless; основа `docs/perf/baseline-swiftshader.json` е комитувана;
   `--check` фаќа регресија во повици/триаголници.
4. Анализа (`analysis.md`) со хипотези каде оди времето и редослед на оптимизации, која ќе се
   потврди со првото мерење на референтниот уред.
5. Сопственикот пушта `?bench` на својот MacBook и резултатот е во `docs/perf/results/`
   (чека сопственикот).
