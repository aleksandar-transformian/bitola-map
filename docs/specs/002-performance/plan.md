# Технички план: мерење и оптимизации

## Фаза А — мерење (спроведено)

```
src/config/perf.js       ← буџети (цели) за референтниот уред + праг за сецкање
src/perf/stats.js        ← прстен, перцентили, удел над праг
src/perf/gpu-timer.js    ← EXT_disjoint_timer_query_webgl2 како штоперица со „кругови“ (без вгнездување)
src/perf/perf.js         ← мерење во живо: интервал, CPU по фаза, GPU по пас; describeEnv() (GPU, DPR, …)
src/perf/bench.js        ← ?bench: сценарија, аблација, панел со табела + JSON (динамички import)
src/perf/report.js       ← буџети ✓/✗, табела како текст, споредба на два извештаја (и за Node)
src/render/pipeline.js   ← instrument(timer): круг по пас (perfName), сенките посебно;
                           setPixelRatio(), setMsaa() во живо; stylePasses
scripts/dev/bench.mjs    ← Playwright runner: SwiftShader или --gpu; JSON → docs/perf/results/; --compare/--check
docs/perf/               ← основа (baseline-*.json) и резултати од мерењата
```

### Како се мери GPU по пас

WebGL2 не дозволува вгнездени `TIME_ELAPSED` мерења. Затоа тајмерот е „штоперица“: секој пас
(обвиткан `render`) прво вика `lap(perfName)`, што го затвора претходното мерење и отвора ново.
`WebGLShadowMap.render` е обвиткан со `lap('shadow')` … `lap('scene')`, па сенките се одвоени од
главниот пас. Решавањето на MSAA (resolve) паѓа во кругот на следниот пас (обично `output`/`gtao`).
GPU работата на композиторот на прелистувачот (canvas → екран, `backdrop-filter`) **не** се гледа
во тајмерот — само во интервалот меѓу кадри; затоа аблацијата има и „без blur зад панелите“.

### Сценарија (`standard`)

| група | погледи | зошто |
|---|---|---|
| ден, двата стила | pregled (6.2 km), center (900 m), shirok-sokak (430 m), close (350 m), top (11 km, одозгора) | од целиот град до улица — различен однос темиња/пиксели |
| ноќ | pregled, shirok-sokak | прозорци, светилки (адитивни точки), светлечки улици |
| лет | pregled → center → shirok-sokak → herakleja (3 × 2.5 s) | движење: натписи, near/far, сенки што ја следат камерата |
| аблација | center, двата стила | цена на секој дел (види spec P3) |

`quick` = двата стила × (pregled, shirok-sokak) + лет — за брза проверка пред/по промена.

### Протокол за мерење на референтниот уред

1. MacBook на струја, затворени други тешки апликации, Chrome (најнов), прозорец преку цел
   екран (не full-screen режим на macOS, ист секој пат), зум на страницата 100 %.
2. `npm run dev`, па `http://127.0.0.1:5173/?bench` (≈ 3 мин). Не допирај ја мапата.
3. Во панелот „Сними JSON“ → `docs/perf/results/<датум>-<commit>-standard-gpu.json`.
4. Провери ја линијата „GPU:“ — мора да е Radeon Pro 555X (ако пишува Intel UHD 630, Chrome
   работи на интегрираната картичка: System Settings → Battery → без „Automatic graphics
   switching“, или во `chrome://gpu`).
5. За споредба пред/по оптимизација: истиот протокол, па
   `node scripts/dev/bench.mjs --compare стар.json нов.json`.
6. (по желба) `?bench` во Safari — нема GPU тајмер, но интервалот меѓу кадри е сепак корисен.

## Фаза Б — оптимизации (редослед по очекувана добивка / ризик за квалитетот)

Секоја оптимизација оди со мерење пред/по на референтниот уред (истиот протокол) и нова основа.
Бројките „очекувано“ се хипотези од анализата (`analysis.md`) — првото мерење на уредот ги
потврдува или менува приоритетите.

| # | оптимизација | влијание на квалитетот | очекувано |
|---|---|---|---|
| Б1 | **Цртање по потреба**: кадар само кога камерата/анимација/премин се менува; инаку 0 % GPU | нема | мирување без загревање → помалку термално забавување на MacBook-от (честа причина за сецкање по неколку минути) |
| Б2 | **MSAA само за сцената**: пост-пасовите во цели без MSAA (сега `EffectComposer` ја клонира MSAA целта, па и `output`/`postcard`/`tiltshift` пишуваат и решаваат 4×) | нема | помалку меморија и пропусност по пас на DPR 2 |
| Б3 | **Шум на хартијата во текстура**: зрното, облаците и „нерамните рабови“ во `postcard` се статични во екранот → пресметај ги еднаш по resize наместо ~70 hash-функции по пиксел | нема (иста функција, испечена) | `postcard` пасот од ALU-тежок во неколку читања од текстура |
| Б4 | **Дрвја**: InstancedMesh по плочки (frustum culling), сенки само за блиските дрвја (или без сенки на дрвјата на преглед), поретки далечни шуми | мал (далечните дрвја се под пиксел) | дрвјата се ~1.08 M триаголници × 2 (сцена + сенки) = > ½ од сите |
| Б5 | **Сенки**: ажурирање само при движење на камерата/сонцето; PCF наместо PCFSoft; помала мапа на преглед | мал | помалку цртање на сцената по кадар |
| Б6 | **Плочки за релјеф и згради** (frustum culling + 2–3 нивоа на детали за релјефот по растојание); индексирани ѕидови | нема / мал | релјефот 842 k триаголници на секој поглед; зградите 1.08 M темиња без индекс |
| Б7 | **Нивоа на квалитет** `високо / средно / ниско / авто` (DPR 2 / 1.5 / 1, сенки, AO во пола резолуција, MSAA) + адаптивна резолуција по измереното GPU време (со хистереза) | контролиран, избор на корисникот | најголем лост на Retina: DPR 2 → 1.5 = −44 % пиксели |
| Б8 | **GTAO („Макета“)**: пола резолуција, 8 примероци; без повторно цртање на сцената за нормали (или замена со запечена AO во темињата) | мал | AO ја црта целата сцена уште еднаш |
| Б9 | **Натписи**: кеширај ги правоаголниците на панелите (resize/промена на UI), ажурирај само кога камерата се движи, пиши `transform` само при промена | нема | CPU по кадар, без принудни layout-и |
| Б10 | **Смена на стил**: `compileAsync` за другиот стил во мирување (`KHR_parallel_shader_compile`) | нема | помал „удар“ при смена |
| Б11 | `backdrop-filter` зад панелите → полу-проѕирна хартија без blur на слаб уред (само ако аблацијата покаже цена) | мал | композитор на macOS |

## Ризици

- **Тајмерот не е секаде**: Safari/Firefox немаат `EXT_disjoint_timer_query_webgl2` → само
  интервал и CPU. Референтното мерење е во Chrome.
- **vsync**: со 60 Hz интервалот не покажува резерва → затоа GPU ms; `--uncapped` во runner-от.
- **Термално забавување**: долго мерење на MacBook-от ги менува бројките со текот на времето →
  мерењето е кратко (~3 мин), а редоследот е фиксен (споредливо меѓу верзии).
- **Две графички картички**: Chrome може да работи на Intel UHD 630 → извештајот го бележи GPU-то.
- **Аблацијата не е адитивна**: збирот на „цените“ не е точно вкупното (споделени трошоци,
  паралелизам на GPU) — служи за редослед, не за точна сметка.
